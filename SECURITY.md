# Security Policy

AuditLane is under active development.

## Reporting a security issue

Please **do not open a public GitHub issue** for:

- exploitable vulnerabilities,
- authentication or authorization bypasses,
- leaked credentials or tokens,
- infrastructure details that could increase operational risk,
- customer or personal data,
- private URLs, internal hostnames, or other sensitive material.

The public repository is not intended for coordinated disclosure of security-sensitive details.

A dedicated private security contact channel will be published before AuditLane is presented as a generally available production service.

Until then, please avoid posting security-sensitive details publicly.

## Scope of this repository

This repository is the public GitHub home of AuditLane.

It does **not** contain:

- the proprietary application source code,
- production secrets,
- private infrastructure configuration,
- internal operational documentation,
- customer data.

## Product security language

AuditLane distinguishes between observed evidence and unavailable evidence.

A missing security signal must not be presented as verified or safe. Passive security findings should remain explicitly bounded by the evidence available to the audit.
